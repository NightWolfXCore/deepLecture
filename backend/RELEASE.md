## Изменения для запуска

Корневой `compose.yaml` запускает интегрированное приложение обычными командами
`docker compose`. `init-env` создаёт отсутствующий `.env` и сохраняет существующий.
В локальном demo-проекте явно заданы MySQL root с пустым паролем и Qwen3 4B;
ручное редактирование конфигурации не требуется. Порт MySQL не публикуется.
Demo использует отдельное имя проекта/volumes `deeplecture-demo`.

Пользователь добавляет полный Qwen3 4B Q4 GGUF в `storage/llm/model.gguf`.
Ollama импортирует его через Modelfile. Whisper/E5 подготавливаются отдельной
командой. Frontend подключён к реальному API; Bootstrap поставляется локально.
Production-мигратор запускается через `docker compose run --rm migrate`.
Команды сборки, импорта, запуска и диагностики, а также публичные маршруты API
приведены в корневом README. Инструкции для отдельной оболочки удалены.

## Ограничения

Сборка настоящего Python-образа дошла до установки ML-зависимостей, но
завершилась ошибкой `no space left on device` в 32-ГБ облачной среде на
слое COPY приложения. Успешная финальная сборка полного образа не подтверждена.
TLS-проверка не отключалась. Веса пользователя не предоставлены; настоящие
Whisper/E5/Qwen, импорт GGUF, скачивание YouTube/Vimeo, качество конспекта,
смысловая релевантность и полный офлайн-сценарий остаются неподтверждёнными.
Первый запуск на целевом компьютере требует скачивания образов/весов и RAM.

Тесты сохраняются в dev/backend отдельными коммитами. В итоговое дерево main
тестовые файлы и workflow backend не включаются.

## Исправление запуска в dev после пользовательского отчёта

В report.txt подтверждена MySQL 1146: отсутствует `deeplecture.search_chunks`.
Это блокирует поиск; очередь и PHP также сообщают ошибки SQL. Лог подтверждает
проблему схемы БД, а не неисправность Qwen. Что произошло при первоначальном
ручном запуске мигратора, по этому отчёту определить нельзя.

В корневом Compose мигратор теперь запускается автоматически. PHP, search
и worker ожидают успешного завершения миграции. Недоступная схема получает
HTTP 503 `DATABASE_SCHEMA_NOT_READY` вместо общей ошибки 500. Readiness проверяет
таблицы лекций и очереди, а не только соединение с MySQL. В журнал PHP добавлен
числовой код SQL-ошибки без текста запроса/секретов. Search повторяет загрузку
модели после временной ошибки запуска; ASR/E5 журналируют только класс ошибки.

На настоящем тестовом MySQL/PHP/FastAPI/FFmpeg прошли 123 Python/HTTP-теста,
включая исчезновение и восстановление таблицы и восстановление модели поиска.
ML-модели в этих тестах явно подменены. Настоящие модели этим не подтверждены.
Изменения остаются в dev до релиза. Пользовательские данные не удалялись.

После освобождения диска отдельно пройден старт корневого Compose на новом
пустом volume MySQL: `up -d --no-build php nginx` автоматически запустил
миграцию, дождался её успешного выхода и только затем запустил PHP/Nginx.
Созданы 8 таблиц; каталог вернул HTTP 200, импорт по ссылке — HTTP 202.
Мигратор выполнялся в лёгком тестовом Python-образе с настоящим PyMySQL;
PHP, SQL и Nginx настоящие, ML/скачивание видео в этой проверке не запускались.
