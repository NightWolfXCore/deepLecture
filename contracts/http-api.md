# HTTP-контракт MVP, версия 1

Статус: спецификация для реализации и frontend mocks, не действующий API.
Публичный префикс `/api/v1`. Браузер использует один origin с PHP API.
JSON в UTF-8. Идентификаторы UUID — строки. Время в содержимом лекции — целые
миллисекунды (`start_ms`, `end_ms`, `duration_ms`); календарные даты — RFC 3339 UTC.
Верхнеуровневый успешный ответ: `data`, для списков дополнительно `meta`.

## Общие правила

- Поля с отсутствующим значением возвращаются как `null`, если это явно показано.
- Списки могут быть пустыми. Индексы `position` начинаются с 0.
- Статусы: `queued`, `extracting`, `transcribing`, `indexing`, `summarizing`, `ready`, `failed`.
- `availability` — источник истины для показа транскрипта, поиска и конспекта.
- Все пользовательские тексты отображаются как текст, не через `innerHTML`.
- PHP не возвращает абсолютные серверные пути, SQL, traceback или секреты.
- Readiness и ответы upstream имеют таймауты; поиск не запускает переиндексацию.

Ошибка:

```json
{
  "error": {
    "code": "LECTURE_NOT_READY",
    "message": "Индекс лекции ещё не готов",
    "details": {}
  },
  "request_id": "b850915c-3f8b-4337-875e-87bb64b9fbc2"
}
```

`details` — объект; для полей формы содержит `fields: {"query": "Обязательное поле"}`.
Общие HTTP-коды: 400 — невалидный JSON, 404 — ресурс не найден, 409 — конфликт
состояния, 413 — слишком большой файл, 415 — неподдерживаемый тип,
422 — ошибка полей, 502 — некорректный ответ Python, 503 — модель/БД/зависимость
недоступна, 504 — таймаут upstream, 500 — внутренняя ошибка.
Nginx должен возвращать согласованную JSON-ошибку для превышения размера API-загрузки.

## 1. Загрузка

`POST /lectures`, `multipart/form-data`:

| Поле | Правило |
|---|---|
| `title` | Обязательно, после trim от 1 до 200 символов |
| `file` | Обязательно, MP4/WebM, до 500 MiB |

`202 Accepted` — файл сохранён, запись и задание созданы. Это ещё не успешное
завершение транскрибации. Ответ:

```json
{
  "data": {
    "id": "11111111-1111-4111-8111-111111111111",
    "title": "Теорема Пифагора",
    "status": "queued",
    "job_id": "22222222-2222-4222-8222-222222222222"
  }
}
```

## 2. Каталог

`GET /lectures?page=1&per_page=20`. `page >= 1`, `per_page` от 1 до 100.
Порядок: `created_at DESC, id DESC`. HTTP 200:

```json
{
  "data": [
    {
      "id": "11111111-1111-4111-8111-111111111111",
      "title": "Теорема Пифагора",
      "status": "ready",
      "duration_ms": 180000,
      "created_at": "2026-10-26T08:00:00Z"
    }
  ],
  "meta": {"page": 1, "per_page": 20, "total": 1}
}
```

## 3. Карточка и статус

`GET /lectures/{id}`. HTTP 200:

```json
{
  "data": {
    "id": "11111111-1111-4111-8111-111111111111",
    "title": "Теорема Пифагора",
    "status": "ready",
    "duration_ms": 180000,
    "media_url": "/media/videos/11111111-1111-4111-8111-111111111111.mp4",
    "availability": {"transcript": true, "search": true, "summary": true},
    "processing": {
      "job_id": "22222222-2222-4222-8222-222222222222",
      "failed_stage": null,
      "error_code": null,
      "error_message": null,
      "can_retry": false
    },
    "created_at": "2026-10-26T08:00:00Z"
  }
}
```

До ffprobe `duration_ms` равен null. `media_url` есть после сохранения файла;
для WebM расширение `.webm`. Произвольный файл по пути пользователя не отдаётся.
`can_retry` истинен только в `failed` и при отсутствии активного задания.
Frontend опрашивает карточку раз в 2 секунды до `ready`/`failed`, прекращает
опрос при уходе со страницы. При недоступности API показывает ошибку и
повторяет с задержкой, не запускает бесконечные частые запросы.

## 4. Транскрипт

`GET /lectures/{id}/transcript`. HTTP 200, все короткие ASR-сегменты MVP,
упорядоченные по `position`; 409 `TRANSCRIPT_NOT_READY`, если не опубликованы.

```json
{
  "data": {
    "lecture_id": "11111111-1111-4111-8111-111111111111",
    "segments": [
      {
        "id": "33333333-3333-4333-8333-333333333333",
        "position": 0,
        "start_ms": 12000,
        "end_ms": 18000,
        "text": "Квадрат гипотенузы равен сумме квадратов катетов."
      }
    ]
  }
}
```

Подсветка: `start_ms <= video.currentTime * 1000 < end_ms`. В паузах
подсвеченного сегмента нет. Нажатие устанавливает `currentTime = start_ms / 1000`.
Субтитры MVP — текстовый блок под видео; дорожка WebVTT возможна позднее.

## 5. Семантический поиск

`POST /search`, JSON:

```json
{
  "lecture_id": "11111111-1111-4111-8111-111111111111",
  "query": "Как связаны стороны прямоугольного треугольника?",
  "limit": 5
}
```

`lecture_id` обязателен в MVP; `query` после trim 1–1000 символов;
`limit` необязателен, по умолчанию 5, диапазон 1–20. HTTP 200:

```json
{
  "data": [
    {
      "chunk_id": "44444444-4444-4444-8444-444444444444",
      "lecture_id": "11111111-1111-4111-8111-111111111111",
      "lecture_title": "Теорема Пифагора",
      "text": "Квадрат гипотенузы равен сумме квадратов катетов.",
      "start_ms": 12000,
      "end_ms": 18000,
      "score": 0.87,
      "playback_url": "/?lecture=11111111-1111-4111-8111-111111111111&t=12"
    }
  ],
  "meta": {"query": "Как связаны стороны прямоугольного треугольника?", "count": 1}
}
```

Порядок — по убыванию cosine similarity, при равенстве по `start_ms`, затем ID.
`score` — сходство векторов от -1 до 1, не вероятность и не процент точности.
MVP возвращает top-k без недоказанного универсального порога релевантности.
Frontend не обещает пользователю, что каждый top-k результат обязательно верен.
404 — лекция отсутствует; 409 `LECTURE_NOT_READY` — индекс не опубликован;
503 `SEARCH_UNAVAILABLE` — модель недоступна. Перекрывающиеся chunks могут дать
похожие результаты; улучшение дедупликации возможно после базовой интеграции.

`playback_url` ведёт на приложение: оно читает `lecture` и `t` (секунды,
возможно дробные), ждёт `loadedmetadata` и перематывает. Это не ссылка на API.

## 6. Конспект и главы

`GET /lectures/{id}/summary`. HTTP 200:

```json
{
  "data": {
    "lecture_id": "11111111-1111-4111-8111-111111111111",
    "text": "В лекции разобрана связь сторон прямоугольного треугольника.",
    "chapters": [
      {
        "id": "55555555-5555-4555-8555-555555555555",
        "position": 0,
        "title": "Связь сторон треугольника",
        "level": 1,
        "start_segment_id": "33333333-3333-4333-8333-333333333333",
        "start_ms": 12000
      }
    ]
  }
}
```

`text` — обычный текст. `level` — 1 (раздел) или 2 (подраздел);
уровень 2 следует за разделом уровня 1. Порядок по `position`, время не убывает.
409 `SUMMARY_NOT_READY` — ещё обрабатывается; 409 `SUMMARY_FAILED` — этап
конспекта завершился ошибкой. Подробности состояния берутся из карточки.
404 — самой лекции нет.

## 7. Повтор обработки

`POST /lectures/{id}/retry`, без тела. Только для `failed`.
`202` возвращает `data: {id, status: "queued", job_id}`.
Повтор полностью сбрасывает результаты и availability в одной транзакции
с созданием нового задания. Видео сохраняется. Это намеренно простой MVP;
возобновление с конкретного этапа — будущее расширение.
Одновременные повторы сериализуются блокировкой лекции: второй получает
409 `PROCESSING_ALREADY_ACTIVE`. 409 `RETRY_NOT_ALLOWED` — лекция не в `failed`.

## 8. Медиа и диагностика

`GET /media/videos/{server-generated-name}` обслуживается Nginx, не PHP JSON API.
Нужны GET/HEAD, Range, 206 Partial Content, Accept-Ranges, Content-Type.

`GET /api/v1/health` — HTTP 200 `{"data":{"status":"ok"}}`, жив ли PHP.
`GET /api/v1/ready` — HTTP 200 или 503, зависимости: БД и Python search-ready;
не возвращает параметры подключения. Heartbeat worker проверяется отдельно
интеграционным тестом выполнения задания; один healthcheck не доказывает работу pipeline.

## 9. Внутренний контракт PHP → Python

`POST /internal/v1/search`: те же `lecture_id`, `query`, `limit`.
Python повторно проверяет готовность индекса и входные данные.
Ответ `200`: `{"data":[{"chunk_id":"UUID","score":0.87}]}`.
PHP получает текст/таймкоды одним SQL-запросом, проверяет принадлежность chunks
лекции и восстанавливает порядок Python. Если индекс сброшен конкурентным retry,
PHP возвращает 409 `LECTURE_NOT_READY`, не частичный набор старых результатов.

FastAPI читает только готовые векторы выбранной лекции; кеш индекса в MVP
не используется. Модель E5 загружается один раз на процесс при старте.
При изменении индекса на стороне worker повторная загрузка модели не нужна.
Успешная готовность Python — `GET /internal/v1/ready`, модель загружена и БД доступна.
Внутренние ошибки тоже имеют envelope `error`; FastAPI validation handlers
приводят стандартный ответ 422 к этому формату.
Таймаут PHP на внутренний поиск — 10 секунд; при превышении возвращается 504.
Внутренний API недоступен из браузера и извне инфраструктуры.

## 10. Задание фронтенду

Экран каталога и загрузки; экран лекции с плеером, статусом обработки,
транскриптом, поиском, результатами, конспектом и оглавлением.
Поиск активен при `availability.search`, даже если конспект ещё генерируется
или завершился ошибкой. Результаты предыдущего запроса не должны заменять
результаты более нового: отменять старый fetch или проверять номер запроса.
Для mock-режима подготовить ready, queued, failed, summarizing, пустой поиск
и ошибки 409/413/503 на основании примеров выше. Mock-данные не доказывают
работоспособность бэкенда; финальная проверка выполняется на реальном API.
